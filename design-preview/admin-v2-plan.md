# Resets AI 内容控制台 v2 方案与实施状态

## 已有能力与缺口

| 领域 | 当前实现 | v2 需要补齐 |
| --- | --- | --- |
| 链接导入 | 读取公开 HTML 的标题、摘要、封面和少量结构化正文；可选 AI 生成卡片文案 | 区分平台适配器、原文提取、图片顺序、视频来源及解析失败原因 |
| 内容存储 | D1 的单条 `body` 文本；图片可手动上传 R2 | 保留原文块结构、图片与视频素材清单、原始文本与站内展示版本 |
| 审核发布 | 草稿/已发布两个状态，表单编辑后直接发布 | 待解析、需协助、待审核、已发布、已下架；发布前完整性检查与版本回退 |
| 前端阅读 | xilo 长文弹窗已可显示全文；其他卡片原先跳转或只有导读 | 所有卡片统一站内弹窗；全文、视频与导读明确标识，末尾统一署名和原链接 |
| 运营 | 热度点击统计；两侧广告是静态示意 | 点击概览、热度榜首、广告位编辑、重置数据源状态 |

## 控制台结构

1. **总览**：待解析、待审核、已发布、阅读量和异常任务；数字从真实数据读取，不放示例指标。
2. **链接导入**：输入 URL 后建立任务；显示来源、作者、发布日期、提取阶段、失败原因。重复链接进入现有文章的修订流程。
3. **审核工作台**：左侧原文块和素材顺序，右侧首页卡片与站内详情预览；逐项确认正文、图片/视频、转载授权和来源署名，最后由站长发布。
4. **内容库**：按平台、类型、状态和日期筛选；支持编辑、撤回、恢复历史版本。保留原始来源链接。
5. **媒体库**：图片缩略图、所属文章、尺寸和存储状态；视频显示嵌入/本站存储方式及可播放检查。
6. **运营**：广告位素材与链接、展示时间；文章点击、每小时热度榜首及来源数据健康。
7. **设置**：平台适配器状态、AI 接口状态和管理员访问控制。密钥只在服务端配置，不在网页存储。

## 内容导入规则

- **原文与编辑文案分开**：原标题、段落、图片、视频顺序保留；首页卡片标题和摘要另行生成，可人工修改。
- **不完整就不自动发布**：拿不到全文、图片或视频时标记“需协助”，列出缺项，不用 AI 补写原文。
- **平台差异明确展示**：先支持可以稳定读取的来源；X 等限制较多的平台需通过已登录浏览器协助、作者提供的导出文件或媒体文件补全。作者授权解决转载许可，不等于平台必然开放抓取接口。
- **媒体可追溯**：每张配图记录原地址、站内地址、所在段落与校验结果；复制到 R2 后再发布，减少外部图片失效。
- **视频处理分级**：可合法嵌入时优先嵌入；需要本站存储时使用作者提供的视频文件和 R2 上传，并在发布前检查播放。大视频、转码和自适应播放须单独评估成本。
- **固定署名**：详情末尾展示作者 ID、来源平台和原文链接；卡片展示作者与日期。

## 推荐实施顺序

1. 审核状态和结构化内容块的数据模型；将现有文章安全迁移，保留旧记录和回退路径。
2. 控制台总览、导入任务与双视图审核；发布前检查完整性和署名。
3. 按平台逐一开发解析器；对失败来源提供协助补全入口，不承诺所有链接都能自动提取。
4. R2 媒体入库与视频播放方案；随后加入广告位、数据统计和系统状态。

## 验收标准

- 给定一篇可读取、已获授权的图文：原文字句与图片顺序可核对，发布后卡片打开站内弹窗，末尾含作者和原链接。
- 给定一个视频：在审核页可确认来源和播放方式，发布后在站内可播放；不能播放则禁止标成已完成全文/视频转载。
- 无法提取的链接进入“需协助”，不出现编造的正文、作者或媒体。
- 审核前不改变公开页面；发布、撤回和恢复均可追踪版本。

## 本地实施状态

- 已实现：审核状态、导入任务、原文与展示稿分离、文章版本、控制台总览/筛选/双视图预览、媒体清单、授权发布检查、YouTube 与 HTTPS MP4 站内播放、四个定时广告位、重置来源可用性显示。
- 已实现但依赖环境：公开 HTML 可读时的通用段落与图片提取；配置 R2 后的图片入库；配置 AI 接口后生成卡片文案。
- 尚有限制：X、B 站等限制来源不保证全文自动提取；普通网页的结构各异，段落和配图必须逐项人工核对；大视频上传、转码与本站托管未实现；点击榜首沿用现有按小时刷新的公开接口。
- 早期静态后台预览已移除，实际后台是 `public/admin.html`。本地和远程已有 D1 均尚需单独执行迁移，代码不会自动改动数据库。
